DOWNSTREAM SERVICE GUIDE - API GATEWAY CONTRACT
Last updated: 2026-04-19

Muc dich
========

Tai lieu nay danh cho cac service nam sau api_gateway, vi du:

- media_service
- finance-service
- media_processing_service
- cac service moi se them sau nay

Muc tieu la thong nhat cach api_gateway van hanh, service phia sau gateway can
tin header nao, can verify gi, route public/protected duoc xu ly ra sao, va khi
them service moi can cau hinh nhu the nao.


1. Nguyen tac tong quat
======================

Client KHONG nen goi truc tiep cac microservice noi bo.

Client goi:

  Frontend / Mobile / External Client
    -> api_gateway
    -> target microservice

Vi du:

  Client -> http://localhost:3000/api/media/...
  Gateway -> http://localhost:4002/api/media/...

Gateway la lop bien ngoai cua he thong:

- Nhan request tu client.
- Kiem tra public/protected route.
- Verify access token cho protected route.
- Xoa cac user headers do client tu gui len de chong spoofing.
- Inject user context headers cho service noi bo.
- Inject internal secret de service biet request di qua gateway.
- Proxy request sang service dich.


2. Public route va protected route
=================================

Gateway dang apply AuthMiddleware cho tat ca route:

  /api/*

Mac dinh, route /api/* la protected.

Protected route yeu cau:

  Authorization: Bearer <access_token>

Public route la route duoc khai bao ro trong api_gateway AuthMiddleware.
Public route khong can Authorization header.

Hien tai public auth routes:

  POST /api/auth/register
  POST /api/auth/login
  POST /api/auth/verify-email
  POST /api/auth/resend-otp
  POST /api/auth/forgot-password
  POST /api/auth/reset-password
  POST /api/auth/refresh

Hien tai co mot so public media GET routes, vi du discovery/stream routes.
Neu media_service them public API moi, phai them route vao publicMediaRoutes
trong api_gateway.

Khuyen nghi:

- API ghi du lieu nen protected mac dinh.
- API doc public thi khai bao public route ro rang trong gateway.
- Khong mo public route trong service ma quen khai bao o gateway, vi gateway
  se chan truoc khi request den service.


3. Gateway verify access token
==============================

Cho protected route, gateway doc:

  Authorization: Bearer <access_token>

Gateway verify token bang:

  ACCESS_TOKEN_SECRET

Gia tri nay phai giong ACCESS_TOKEN_SECRET cua identity-service, vi
identity-service la noi ky access token.

Neu verify fail, request se bi reject tai gateway, service dich khong nhan
duoc request.

Service downstream khong can verify JWT neu service tin gateway headers va
verify x-internal-secret.


4. Headers gateway inject sang service
=====================================

Khi access token hop le, gateway inject cac headers sau sang service dich:

  x-user-id
    Gia tri lay tu JWT claim sub.

  x-user-email
    Gia tri lay tu JWT claim email.

  x-user-role
    Gia tri lay tu JWT claim role neu co.

  x-internal-secret
    Gia tri lay tu INTERNAL_GATEWAY_SECRET.
    Service phai verify header nay truoc khi tin x-user-*.

  x-request-id
    Request id do gateway tao hoac forward de log/tracing.

Quan trong:

- Client ben ngoai KHONG duoc tu set cac header nay.
- Gateway da xoa cac header nay truoc khi inject lai:

  x-user-id
  x-user-email
  x-user-role
  x-internal-secret
  x-request-id

- Service downstream chi nen tin x-user-* neu x-internal-secret hop le.


5. Contract cho service downstream
==================================

Moi service nam sau gateway nen co guard/middleware noi bo:

1. Doc header:

   x-internal-secret

2. So sanh voi env:

   INTERNAL_GATEWAY_SECRET

3. Neu khong khop:

   Tra 401 Unauthorized.

4. Neu route can user:

   Doc x-user-id tu header.
   Neu thieu x-user-id thi tra 401 Unauthorized.

5. Neu route can role:

   Doc x-user-role tu header.
   Check role theo rule cua service.

Pattern hien co trong media_service:

- InternalGatewayGuard verify x-internal-secret.
- CurrentUserId decorator doc x-user-id.
- CurrentUserRole decorator doc x-user-role.
- SkipInternalGatewayGuard danh dau public API khong can internal secret.

Khuyen nghi cac service khac nen copy pattern tu media_service thay vi tu verify
JWT truc tiep o tung controller.


6. Khi nao service tu verify JWT?
=================================

Mac dinh: KHONG can.

Service nen tin gateway headers sau khi verify x-internal-secret.

Chi tu verify JWT trong service khi co ly do ro rang, vi du:

- Service duoc goi truc tiep boi internal client khong di qua gateway.
- Service expose endpoint rieng ngoai gateway.
- Can defense-in-depth cho API rat nhay cam.

Neu service tu verify JWT:

- Phai dung ACCESS_TOKEN_SECRET giong identity-service.
- Chi chap nhan token type=access.
- Khong bao gio chap nhan refresh token cho service API.
- Van nen reject spoofed x-user-* neu request khong co x-internal-secret hop le.


7. Route mapping hien tai trong gateway
======================================

Gateway route -> target service:

  /api/auth/*
    -> identity-service
    -> rewrite thanh /api/identity/auth/*

  /api/user/*
    -> identity-service
    -> rewrite thanh /api/identity/user/*

  /api/media/*
    -> media_service
    -> giu nguyen path /api/media/*

  /api/wallet/*
    -> wallet/finance service neu duoc cau hinh

  /api/payment/*
    -> payment/finance service neu duoc cau hinh

  /api/process/*
    -> media_processing_service neu duoc cau hinh

Luu y:

- Identity-service co global prefix /api/identity nen gateway phai rewrite
  /api/auth va /api/user.
- Media-service hien dang dung public path /api/media nen gateway giu nguyen.
- Service moi can thong nhat public path ngay tu dau, vi gateway se proxy theo
  path do.


8. Them service moi vao gateway
===============================

Vi du them finance-service voi public prefix:

  /api/finance/*

Can lam cac buoc:

1. Them env trong api_gateway:

   FINANCE_SERVICE_URL=http://localhost:<port>

2. Them config getter trong ServiceConfigService:

   financeServiceUrl

3. Them route rule trong ProxyMiddleware:

   '^/api/finance': this.serviceConfigService.financeServiceUrl

4. Them rate limit config neu can:

   '^/api/finance': 'financeService'

5. Quyet dinh public routes:

   Neu public:
     Them pattern vao AuthMiddleware public rules.

   Neu protected:
     Khong them public rule. Gateway se yeu cau Authorization Bearer token.

6. Trong finance-service:

   - Them INTERNAL_GATEWAY_SECRET vao env.
   - Them guard verify x-internal-secret.
   - Dung x-user-id cho user identity.
   - Dung x-user-role neu can phan quyen.
   - Log x-request-id de trace request.


9. Env service downstream can co
================================

Moi service phia sau gateway nen co:

  INTERNAL_GATEWAY_SECRET=<same value as api_gateway>

Neu service tu verify JWT thi them:

  ACCESS_TOKEN_SECRET=<same value as identity-service>

Neu service chi tin gateway headers thi khong bat buoc can ACCESS_TOKEN_SECRET.

Khuyen nghi:

- Khong commit secret that vao git.
- .env.example chi dung placeholder.
- Secret that nen lay tu Docker/Kubernetes/secret manager.


10. Cach service doc user context
================================

Controller protected route nen lay user id tu header gateway.

Vi du logic tong quat:

  userId = request.headers["x-user-id"]

Neu userId thieu:

  401 Unauthorized

Neu role can thiet:

  role = request.headers["x-user-role"]

Neu service can email:

  email = request.headers["x-user-email"]

Khong nen lay userId tu request body cho protected action, vi body la input cua
client va co the bi gia mao.


11. Public API trong service
============================

Neu endpoint public:

- Gateway phai cho qua route do.
- Service co the dung decorator/guard skip internal gateway guard.
- Endpoint public khong nen doc x-user-id bat buoc.
- Neu endpoint public co optional user context, can xu ly truong hop khong co
  x-user-id.

Vi du public media routes:

- Discovery videos.
- Public channel detail.
- HLS master playlist/segments.


12. Protected API trong service
===============================

Neu endpoint protected:

- Gateway yeu cau Authorization Bearer access token.
- Gateway verify token va inject x-user-* headers.
- Service verify x-internal-secret.
- Service doc x-user-id tu header.

Flow:

  Client
    -> Authorization: Bearer access token
    -> api_gateway
    -> verify JWT
    -> inject x-user-id/x-user-email/x-user-role/x-internal-secret
    -> target service
    -> service verify x-internal-secret
    -> service dung x-user-id trong use case


13. Request id va logging
=========================

Gateway inject:

  x-request-id

Service downstream nen:

- Lay x-request-id tu header.
- Gan vao logger context.
- Log request lifecycle voi requestId.
- Khi publish event/message, neu co traceId thi nen map tu requestId hoac trace
  context hien co.

Muc tieu:

- Mot request tu frontend qua gateway den nhieu service co the trace duoc.


14. Loi thuong gap
==================

1. Service bao Missing or invalid internal gateway secret

   Nguyen nhan:

   - Request goi truc tiep service, khong qua gateway.
   - Gateway chua inject x-internal-secret.
   - INTERNAL_GATEWAY_SECRET cua gateway va service khac nhau.

2. Service bao Missing user identity from gateway headers

   Nguyen nhan:

   - Route dang public nen gateway khong verify token va khong inject x-user-id.
   - Client khong gui Authorization header cho protected API.
   - Gateway public route config bi mo qua rong.
   - Controller protected dang dung CurrentUserId nhung request khong co x-user-id.

3. Gateway bao Invalid or expired token

   Nguyen nhan:

   - Client gui access token het han.
   - Client gui refresh token vao Authorization.
   - ACCESS_TOKEN_SECRET cua gateway khac identity-service.

4. API qua gateway bi 404 nhung goi truc tiep service duoc

   Nguyen nhan:

   - Gateway route rule chua co prefix do.
   - Gateway rewrite sai path.
   - Service co global prefix khac public gateway path.
   - Target service URL sai port/host.


15. Checklist truoc khi merge service moi
=========================================

Gateway:

  [ ] Co SERVICE_URL trong env/config.
  [ ] Co route rule proxy.
  [ ] Co rate limit config neu can.
  [ ] Public routes duoc khai bao ro.
  [ ] Protected routes khong bi dua vao public list.
  [ ] Path rewrite dung voi global prefix cua target service.

Target service:

  [ ] Co INTERNAL_GATEWAY_SECRET.
  [ ] Co guard/middleware verify x-internal-secret.
  [ ] Protected route lay userId tu x-user-id, khong lay tu body.
  [ ] Role check dung x-user-role neu can.
  [ ] Public route co co che skip guard ro rang.
  [ ] Log x-request-id.
  [ ] .env.example khong chua secret that.

Integration:

  [ ] Goi protected API khong token -> gateway tra 401.
  [ ] Goi protected API voi access token hop le -> service nhan x-user-id.
  [ ] Goi truc tiep service khong x-internal-secret -> service tra 401.
  [ ] Public API qua gateway khong token -> thanh cong neu dung public route.
  [ ] ACCESS_TOKEN_SECRET khop giua gateway va identity-service.
  [ ] INTERNAL_GATEWAY_SECRET khop giua gateway va target service.


16. Ket luan ngan gon cho team service
=====================================

- Service khac khong can biet refresh token.
- Service khac chi lam viec voi access-token-derived context do gateway inject.
- Service khac phai verify x-internal-secret truoc khi tin x-user-*.
- User id dung trong business logic phai lay tu x-user-id.
- Client khong duoc tu gui x-user-*; gateway se xoa va inject lai.
- Route nao public/protected la quyet dinh o gateway truoc, service guard la
  lop bao ve thu hai.
